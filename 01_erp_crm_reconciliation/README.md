# Сверка заказов между ERP и CRM

## Задача

Построить контроль сверки заказов между ERP и CRM за последние 60 дней.

В обеих системах один заказ может иметь несколько версий записи, поэтому перед сравнением необходимо определить актуальное состояние заказа по максимальному `updated_at`.

Из проверки исключаются заказы из `excluded_orders`.

## Контролируемые расхождения

- `missing_in_crm` — заказ есть в ERP, но отсутствует в CRM
- `missing_in_erp` — заказ есть в CRM, но отсутствует в ERP
- `customer_mismatch` — для одного `order_id` указаны разные клиенты
- `amount_mismatch` — сумма отличается более чем на 2% относительно ERP

Один заказ может получить несколько типов ошибок одновременно.

## Подход

1. Определить актуальную версию каждого заказа через `ROW_NUMBER()`.
2. Исключить заказы, не участвующие в сверке.
3. Проверить наличие `order_id` в обеих системах.
4. Для совпавших заказов сравнить клиента и сумму.
5. Объединить найденные проблемы в единый набор данных.
6. Добавить информацию о клиенте и сегменте.

## Допущения

- `order_id` является бизнес-ключом заказа в обеих системах.
- Актуальной считается запись с максимальным `updated_at`.
- ERP используется как база для расчёта относительного отклонения суммы.
- Порог 2% является бизнес-правилом и может быть изменён.
- Отсутствие клиента в справочнике не должно скрывать найденную ошибку.

## Результат

Запрос формирует единый отчёт по нарушениям синхронизации заказов с указанием причины расхождения и позволяет использовать результат как основу для регулярного контроля интеграции ERP и CRM.

**SQL:** CTE, оконные функции, anti-join, `NOT EXISTS`, `UNION ALL`.
