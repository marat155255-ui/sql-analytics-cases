# Сверка заказов между ERP и CRM

## Задача

Проверить корректность синхронизации заказов между ERP и CRM за последние 60 дней.

В обеих системах один заказ может иметь несколько версий записи. Перед сверкой необходимо определить актуальное состояние заказа по последнему `updated_at`.

Заказы из таблицы `excluded_orders` исключаются из проверки.

## Исходные таблицы

- `erp_orders` — заказы ERP
- `crm_orders` — заказы CRM
- `customers` — справочник клиентов
- `excluded_orders` — заказы, исключённые из сверки по бизнес-правилам

## Проверяемые проблемы

- `missing_in_crm` — заказ есть в ERP, но отсутствует в CRM
- `missing_in_erp` — заказ есть в CRM, но отсутствует в ERP
- `customer_mismatch` — для одного заказа отличаются клиенты
- `amount_mismatch` — сумма отличается более чем на 2% относительно ERP

Если у заказа одновременно обнаружено несколько проблем, каждая выводится отдельной строкой.

## Логика решения

1. Через `ROW_NUMBER()` определяется последняя версия каждого заказа.
2. `NOT EXISTS` исключает заказы, которые не должны участвовать в сверке.
3. Через `LEFT JOIN` выявляются отсутствующие заказы.
4. Совпавшие `order_id` проверяются на расхождение клиента и суммы.
5. Разные типы ошибок объединяются через `UNION ALL`.
6. Через справочник `customers` добавляются имя клиента и сегмент.

## Ключевые особенности

- учитывается гранулярность данных и наличие нескольких версий заказа;
- отсутствие заказа в одной системе не приводит к потере проблемы из результата;
- деление на ноль обрабатывается отдельно;
- ERP используется как базовая система при расчёте процентного отклонения;
- справочник клиентов подключается через `LEFT JOIN`, поэтому отсутствие клиента в справочнике не скрывает найденное расхождение.

## Использованные SQL-инструменты

`CTE` · `ROW_NUMBER()` · `PARTITION BY` · `LEFT JOIN` · `INNER JOIN` · `NOT EXISTS` · `UNION ALL` · `CASE` · `ABS`

## Бизнес-смысл

Запрос может использоваться как контроль качества интеграции между двумя информационными системами и позволяет быстро разделить ошибки синхронизации по типам для дальнейшей проверки.
